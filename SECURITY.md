# Avid Media Composer Post-Production Reference

Avid Media Composer is an independent reference for video editing and post-production workflows associated with the commercial application. This repository does not distribute Media Composer, media, plugins, or an installer. It focuses on editorial organization and handoffs across production, assistant editing, finishing, and media management.

## Overview

Long-form editorial projects depend on stable media identity, bins, sequences, metadata, and shared-storage practices. Proxy and source media must remain related through documented relink and conform steps. A handoff should record project revision, media status, export intent, and any known offline or substituted assets. Editorial notes are not a substitute for checking the actual project and delivery specifications.

## Features and Topics

- **Project organization:** Plan bins, naming, sequence versions, markers, and editorial notes.
- **Media provenance:** Track source IDs, card or camera metadata, proxy relationships, and relink context.
- **Shared workflows:** Document checkout, locking, storage paths, and responsibility for project changes.
- **Editorial review:** Manage cuts, notes, turnovers, and version comparisons without losing prior decisions.
- **Finishing handoff:** Specify sequence version, frame rate, handles, audio layout, and requested outputs.
- **Media troubleshooting:** Isolate offline media, duplicate identifiers, cache, and storage connectivity symptoms.

## Use Cases

Assistant editors can prepare turnover notes; editors can preserve sequence history; media managers can track relinks; post teams can define conform expectations; support staff can reproduce offline-media issues with a concise record.

## FAQ

### Does a proxy replace original camera media?
No. Preserve source media and document proxy relationships for conform and archival work.

### What should a turnover include?
At minimum, identify the sequence revision, media state, frame rate, handles, audio layout, and requested deliverables.

### Why record shared-storage changes?
It helps separate project state issues from access, locking, and media-path problems.
